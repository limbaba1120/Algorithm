# 체육복

- 문제 번호: 42862
- 난이도: Level 1
- 풀이 날짜: 2026-08-06
- 핵심 자료구조: `HashSet`
- 핵심 알고리즘: 그리디
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42862

## 문제 설명

일부 학생은 체육복을 도난당했고, 일부 학생은 여벌 체육복을 가지고 있다. 여벌 체육복은 학생 번호가 바로 앞이거나 바로 뒤인 학생에게만 빌려줄 수 있다. 체육복을 입고 수업에 참여할 수 있는 학생 수의 최댓값을 구한다.

한 학생이 도난당한 학생이면서 동시에 여벌 체육복을 가진 학생일 수도 있다. 이 학생은 자신의 여벌 체육복을 입어야 하므로 다른 학생에게 빌려줄 수 없다.

## 핵심 접근

도난당한 학생과 여벌 체육복을 가진 학생을 각각 `Set`으로 관리한다.

```java
Set<Integer> lostSet = new HashSet<>();
Set<Integer> reserveSet = new HashSet<>();
```

풀이 순서는 다음과 같다.

1. `lost`와 `reserve`를 각각 `Set`에 저장한다.
2. 두 집합에 모두 속한 학생을 양쪽에서 제거한다.
3. 현재 체육복이 있는 학생 수를 `n - lostSet.size()`로 계산한다.
4. 1번 학생부터 차례대로 확인하며 앞번호, 뒷번호 순서로 체육복을 빌린다.
5. 빌리는 데 성공할 때마다 정답을 1 증가시킨다.

## 중복 학생을 먼저 처리하는 이유

예를 들어 3번 학생이 `lost`와 `reserve`에 모두 들어 있다면, 3번 학생은 여벌 체육복으로 자신의 도난을 해결한다. 따라서 3번 학생은 더 이상 체육복이 없는 학생도 아니고, 다른 학생에게 빌려줄 수 있는 학생도 아니다.

```java
for (int student : lost) {
    if (reserveSet.contains(student)) {
        lostSet.remove(student);
        reserveSet.remove(student);
    }
}
```

여기서는 원본 배열 `lost`를 순회하면서 `lostSet`을 수정하므로 안전하다. `lostSet` 자체를 순회하면서 `lostSet.remove()`를 호출하면 `ConcurrentModificationException`이 발생할 수 있다.

## 번호순으로 앞번호부터 확인하는 이유

`HashSet`은 순회 순서를 보장하지 않는다. 따라서 `lostSet`을 직접 순회하지 않고 `1`부터 `n`까지 순회하며 도난 여부를 확인한다.

```java
for (int student = 1; student <= n; student++) {
    if (!lostSet.contains(student)) {
        continue;
    }

    if (reserveSet.remove(student - 1)) {
        answer++;
    } else if (reserveSet.remove(student + 1)) {
        answer++;
    }
}
```

앞번호의 체육복부터 확인하는 것은 뒤에 있는 학생이 빌릴 기회를 남기는 그리디 선택이다.

```text
lost    = [2, 4]
reserve = [1, 3]

2번이 3번에게 먼저 빌리면 4번은 빌릴 수 없다.
2번이 1번에게 빌리면 4번은 3번에게 빌릴 수 있다.
```

## 이 문제에서 사용하는 `Set` 연산

`Set`은 중복된 값을 저장하지 않는 자료구조다. 이 문제에서는 학생 번호의 존재 여부를 확인하고, 사용한 체육복을 제거하는 데 사용한다.

| 연산 | 의미 | 반환값 |
|---|---|---|
| `add(value)` | 값을 추가한다. | 새로 추가되면 `true` |
| `contains(value)` | 값이 있는지 확인한다. | 있으면 `true` |
| `remove(value)` | 값을 제거한다. | 제거하면 `true` |
| `size()` | 저장된 값의 개수를 구한다. | `int` |
| `isEmpty()` | 비어 있는지 확인한다. | 비어 있으면 `true` |
| `clear()` | 모든 값을 제거한다. | 반환값 없음 |

이 풀이에서는 `remove()`의 반환값으로 존재 확인과 제거를 한 번에 처리한다.

```java
if (reserveSet.remove(student - 1)) {
    answer++;
}
```

앞번호 학생이 `reserveSet`에 있으면 그 번호를 제거하고 `true`를 반환한다. 제거된 체육복은 다른 학생이 다시 빌릴 수 없으므로 중복 대여도 자연스럽게 방지된다.

## 자주 사용하는 집합 연산

두 `Set`이 있을 때 다음 연산도 사용할 수 있다. 원본 `Set`의 내용이 변경된다는 점에 주의한다.

```java
set.addAll(otherSet);      // 합집합: 다른 Set의 값들을 추가
set.retainAll(otherSet);   // 교집합: 공통된 값만 유지
set.removeAll(otherSet);   // 차집합: 공통된 값들을 제거
set.containsAll(otherSet); // 다른 Set의 모든 값을 포함하는지 확인
```

## `HashSet`의 특징과 주의점

- 같은 값을 중복해서 저장하지 않는다.
- `add()`, `contains()`, `remove()`의 평균 시간 복잡도는 `O(1)`이다.
- 값의 저장 순서와 순회 순서를 보장하지 않는다.
- 순서가 필요하면 별도로 정렬하거나 번호순으로 반복해야 한다.
- 향상된 `for`문으로 순회 중인 같은 `Set`을 직접 수정하면 안 된다.

## 복잡도

- 시간 복잡도: `O(n + lost.length + reserve.length)`, 문제 조건에서는 `O(n)`
- 공간 복잡도: `O(lost.length + reserve.length)`

## 전체 코드

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int solution(int n, int[] lost, int[] reserve) {
        Set<Integer> lostSet = new HashSet<>();
        Set<Integer> reserveSet = new HashSet<>();

        for (int student : lost) {
            lostSet.add(student);
        }

        for (int student : reserve) {
            reserveSet.add(student);
        }

        for (int student : lost) {
            if (reserveSet.contains(student)) {
                lostSet.remove(student);
                reserveSet.remove(student);
            }
        }

        int answer = n - lostSet.size();

        for (int student = 1; student <= n; student++) {
            if (!lostSet.contains(student)) {
                continue;
            }

            if (reserveSet.remove(student - 1)) {
                answer++;
            } else if (reserveSet.remove(student + 1)) {
                answer++;
            }
        }

        return answer;
    }
}
```
