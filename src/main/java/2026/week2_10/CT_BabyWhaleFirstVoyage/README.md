# 아기 고래의 첫 항해

- 풀이 날짜: 2026-10-11
- 플랫폼: 코드트리
- 유형: 시뮬레이션, BFS, 최단 경로
- 문제 링크: https://www.codetree.ai/ko/frequent-problems/samsung-sw/problems/baby-whale-first-voyage/description
- 풀이 코드: [Main.java](Main.java)

## 1. 전체 흐름

목표는 암초를 제외한 모든 바다를 방문하는 것이다. 전체 탐험 거리를 최소화하는 문제가 아니라, 문제에서 정한 이동 규칙을 그대로 구현한다.

1. 시작 위치를 방문 처리하고 출력 목록에 추가한다.
2. `exploreOneStep()`으로 인접한 미방문 바다에 한 칸 이동한다. 성공하면 다시 이 단계를 반복한다.
3. 주변에 미방문 바다가 없으면 `findTarget()`으로 가장 가까운 미방문 바다를 고른다.
4. `moveToTarget()`으로 목적지까지 이동한 뒤 인접 탐험을 다시 시작한다.
5. 도달 가능한 미방문 바다가 없으면 종료한다.

출력에는 시작 칸과 처음 방문한 바다의 좌표를 넣는다. 이미 방문한 칸을 다시 지나갈 때는 출력하지 않는다.

## 2. 고래 상태와 방향

- `board[row][col]`: 바다 `0`, 암초 `1`.
- `isVisited[row][col]`: 고래가 실제로 방문했는지 기록하는 2차원 배열.
- `r`, `c`, `d`: 고래의 현재 행, 열, 방향.
- `answer`: 처음 방문한 좌표를 순서대로 저장한다.

사용자가 작성한 구조에 맞춰 변수와 메서드는 `static`으로 유지한다. 좌표는 1부터 사용하며 방향 번호는 문제와 같은 `1=상, 2=하, 3=좌, 4=우`다.

```java
static int[] dx = {0, -1, 1, 0, 0}; // 행 변화
static int[] dy = {0, 0, 0, -1, 1}; // 열 변화
```

이 번호는 시계 방향 순서가 아니므로 회전을 단순히 `(d + 1) % 4`로 계산하면 안 된다. 현재 방향별로 `switch`에서 확인 순서를 정한다.

## 3. 1단계: 인접 탐험

현재 방향을 기준으로 직진, 좌회전, 우회전, 뒤쪽 순서로 확인한다.

```text
상: 상 → 좌 → 우 → 하
하: 하 → 우 → 좌 → 상
좌: 좌 → 하 → 상 → 우
우: 우 → 상 → 하 → 좌
```

격자 안에 있고, 암초가 아니며, 아직 방문하지 않은 칸이면 이동한다. 위치와 방향을 갱신하고 방문 기록과 출력 목록에 추가한다.

`exploreOneStep()`은 한 칸 이동했으면 `true`, 네 방향 모두 불가능하면 `false`를 반환한다. 주변에 갈 곳이 없다는 것은 전체 탐험이 끝났다는 뜻이 아니다. 멀리 미방문 바다가 남아 있을 수 있으므로 2단계로 넘어간다.

## 4. BFS 거리 배열과 실제 방문 기록의 차이

`getDistances(startR, startC)`는 출발점에서 모든 칸까지의 최소 이동 횟수를 구한다. 이 함수 자체는 고래를 움직이지 않는다.

- `dist == -1`: 이번 BFS에서 아직 도달하지 않은 칸. 탐색이 끝난 뒤에도 -1이면 도달 불가능하다.
- `dist == 0`: BFS 출발점.
- `dist == 1, 2, 3, ...`: 출발점에서 필요한 최소 이동 횟수.

```java
if (board[nr][nc] == 1 || dist[nr][nc] != -1) {
    continue;
}
```

암초이거나 이번 BFS에서 이미 거리를 알아낸 칸이면 다시 큐에 넣지 않는다. `dist[nr][nc] != -1`은 아직 확인하지 않은 다음 칸으로의 탐색을 막는 조건이 아니다. 새 칸은 여전히 -1이므로 현재 거리보다 1 큰 값을 저장하고 큐에 넣는다.

```java
dist[nr][nc] = dist[row][col] + 1;
queue.offer(new int[]{nr, nc});
```

```text
[출발점] [바다] [바다] [바다]
   0       1      2      3
```

이미 방문한 바다도 2단계에서는 지나갈 수 있다. 따라서 BFS에서 `isVisited`를 통과 금지 조건으로 사용하면 안 된다. `isVisited`와 이번 탐색용 `dist`는 별도로 관리한다.

## 5. findTarget: 목적지를 먼저 결정

현재 고래 위치에서 `getDistances(r, c)`를 호출한다. 암초, 이미 실제로 방문한 칸, 도달 불가능한 칸을 목적지 후보에서 제외한다.

목적지 우선순위는 다음과 같다.

1. 현재 고래 위치에서의 최단 거리가 작다.
2. 거리가 같으면 행 번호가 작다.
3. 행도 같으면 열 번호가 작다.

행과 열을 오름차순으로 순회하면서 거리가 더 짧을 때만 후보를 갱신한다. 비교 조건을 `<`로 쓰면 같은 거리에서 먼저 확인한 좌표가 유지된다.

이 시점에는 목적지만 정했으며 고래의 위치는 바뀌지 않는다. 후보가 없다면 `null`을 반환한다.

## 6. moveToTarget: 정해진 목적지까지 실제 이동

이번에는 `getDistances(targetR, targetC)`를 호출한다. 바다의 이동은 양방향이므로 목적지에서 각 칸까지의 거리는 각 칸에서 목적지까지 남은 거리와 같다.

두 BFS의 용도가 다르다.

```text
고래 위치에서 BFS → 어디로 갈지 결정
목적지에서 BFS    → 그곳까지 어떤 길로 갈지 결정
```

목적지에서 BFS를 한다고 고래가 목적지로 이동하거나 목적지를 다시 선택하는 것은 아니다. 고래는 아직 출발 위치에 있다.

```java
if (dist[nr][nc] != dist[r][c] - 1) {
    continue;
}
```

현재 칸의 남은 거리가 3이라면 다음 칸은 반드시 2여야 한다. `3 → 2 → 1 → 0`으로 이동하면 최단 경로로 도착한다. 좌표만 보고 목적지 쪽으로 이동하면 암초 때문에 막다른 길로 갈 수 있어 거리 정보가 필요하다.

조건을 만족하는 이웃이 여러 개라면 고정된 좌, 하, 우, 상 순서로 선택한다. 이 우선순위는 고래가 바라보는 방향과 무관하다. 매 이동마다 `d`를 갱신하므로 도착했을 때 마지막 이동 방향이 남는다.

## 7. 그림으로 따라가기

`#`은 암초이며 고래는 (2, 2)에서 위쪽을 보고 시작한다.

```text
       1열  2열  3열
1행     #    A    #
2행     B   고래   C
3행     #    #    #
```

1. 직진하여 A로 이동한다. 시작 칸과 A는 방문한 상태다.
2. A 주변에는 미방문 바다가 없다. A에서 BFS를 하면 B와 C 모두 거리가 2다.
3. B와 C는 행도 같으므로 열이 작은 B를 목적지로 고른다. 고래는 아직 A에 있다.
4. B에서 BFS를 하면 다음과 같이 목적지까지 남은 거리가 표시된다.

```text
       #    2    #
       0    1    2
       #    #    #
       B
```

5. 고래는 A에서 시작 칸을 거쳐 B로 간다. 남은 거리는 2 → 1 → 0으로 줄어든다.
6. B에서도 인접 탐험이 불가능하므로 남은 C를 목적지로 골라 이동한다.
7. 모든 바다를 방문했다. 출력 순서는 시작 칸, A, B, C다. 중간에 다시 지나간 시작 칸은 출력하지 않는다.

## 8. 예제와 복잡도

사용자가 제공한 문제 예제의 출력 순서는 다음과 같다.

```text
4 4
4 3
3 3
2 3
1 3
2 2
2 1
3 1
3 2
1 1
2 4
```

BFS 한 번은 `O(N²)`이고, 2단계 호출 횟수를 K라고 하면 전체 시간은 `O((K + 1)N²)`이다. 각 2단계는 최소 하나의 새 칸을 방문하므로 K는 최대 `O(N²)`이며, 단순 상한은 `O(N⁴)`이다. 거리 배열, 큐, 방문 기록의 추가 공간은 `O(N²)`다. 제공된 문제 본문에는 제한 조건의 수치가 빠져 있어 최대 입력에서의 실행 시간은 별도로 확인해야 한다.

같은 저장소에 다른 `Main` 클래스가 있으므로 이 문제는 해당 `Main.java` 파일을 개별 컴파일해 실행한다.
